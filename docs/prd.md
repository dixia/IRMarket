## 〇、Monoracle 机制速览（认知基线）

> ⚠️ 以下为 Monoracle 合约源码中的真实行为。PRD 中涉及 Monoracle 的一切表述都应以此为准。

Monoracle **不是一个多节点聚合、依赖链下数据源的预言机（oracle，原文误作"预言家"）**。它是一个"报价 + 免许可否决仲裁"的链上价格市场：

1. **报价（quote）**：provider 调用 `submitQuote(base, quote, baseAmount, quoteAmount)`，同时质押 **两种** ERC20（标的 base + 计价 quote），确定一个对价：
   `price = quoteAmount × 1e18 / baseAmount`（即"1 单位标的 = 多少 quote 计价币"，如 1 LLM = 若干 HKD）。
2. **双边抵押**：报价上链即锁定 provider 的 base 与 quote 双边抵押品。
3. **验证窗口**：固定 **2 slots（≈600ms，Monad 300ms 出块）**，窗口内报价为 `ACTIVE`。
4. **否决仲裁（veto）**：窗口内任何人可以对照自己掌握的"真实市场价"进行仲裁：
   - 报价偏低（real > quoted）→ `vetoUnderpriced`：仲裁者支付 quoteAmount，换走 baseAmount（低价买入真实更贵的标的）；
   - 报价偏高（real < quoted）→ `vetoOverpriced`：仲裁者支付 baseAmount，换走 quoteAmount（高价卖出真实更便宜的标的）。
   - 被否决的报价作废（`VETOED_*`），不进价格源。
5. **结算（settle）**：窗口内无人否决，则任何人（免许可）调用 `settleValidQuote`，该报价成为该资产对的 **canonical 有效价格**（`latestValidQuoteId` 指向它）。
6. **提取（withdraw）**：provider 事后退还——有效报价原额取回；被否决则 **加倍取回另一侧**（抵押惩罚，即否决-套利的风险/收益）。

**IRMarket 的借用边界（🔁，〔v0.7 R1〕能力归属表）**：

| 能力 | 由谁提供 | 说明 |
|------|----------|------|
| 报价提交 / 报价账本 / 事件 | 🔁 Monoracle 原生 | `submitQuote` + `quotes` mapping + `QuoteSubmitted` 等事件 |
| 双边抵押托管 | 🔁 Monoracle 原生 | base+quote 抵押锁在 **Monoracle 合约内部**，仅 provider 可 `withdrawProviderFunds` 取回 |
| 验证窗口 / 否决仲裁 | 🔁 Monoracle 原生 | 固定 `VERIFICATION_SLOTS=2`；`vetoUnderpriced` / `vetoOverpriced` |
| 有效价结算 | 🔁 Monoracle 原生 | `settleValidQuote` 免许可；`latestValidQuoteId` 指向最新 canonical 价 |
| 实时参考价读取 | 🔁 Monoracle 原生 | `getLatestPrice(base, quote)` → `(price, settledSlot, exists)` |
| 市场创建 | IRMarket 自建 | 标的/期限/做市商配置、池初始化（`createMarket`） |
| 持仓账本 / PNL 计算 | IRMarket 自建 | 份数、开仓参考价快照、线性差价 PNL（D-02） |
| 期权资金池 | IRMarket 自建 | 用户本金 / 盈亏池 / 做市商收益三账户（⚠️ 与 Monoracle 抵押品**完全分离**，见下） |
| 手续费 / 升水 | IRMarket 自建 | 1% 定价层（模型待 Q3 确认） |
| 到期结算触发 | IRMarket 自建 + bot | 读 Monoracle 价，按 D-04/D-06 自动结算 |

> 〔v0.7 R2〕**关键事实**：Monoracle 的双边抵押品托管在 **Monoracle 合约内部**（`submitQuote` 时 `safeTransferFrom` 入合约），IRMarket 合约**没有任何函数可以动用**它。因此一切"用 Monoracle 抵押资金承接期权盈亏/平仓"的表述都是机制误解——Monoracle 只负责**出价（价格可信度）**，期权盈亏的资金必须由 **IRMarket 自有资金池**承担（见 §九 B1、§十 Q1）。

> ⚠️ 因此：**用户买"看涨/看跌"期权 ≠ Monoracle 的 veto 方向**。用户是在 IRMarket 里交易期权仓位；veto 是链上任意套利者针对 **provider 的报价** 做的价格可信度仲裁，与用户的开仓方向完全无关（详见 2.1 修正）。

## 一、产品概述

### 1.1 产品定位

IRMarket 是部署在 Monad 区块链上的 **链上奇异期权市场**，支持任意具备公开价格的资产作为期权标的（例：A股、港股现货、Labubu），底层基于 **Monoracle 否决-套利原语** 提供价格结算，全程不依赖链下数据源与中心化验证节点。

产品UI与交互对标轻量化预测市场形态，用户仅需对标的价格做「看涨/看跌」的简单判断即可开仓，无需理解复杂期权术语。

### 1.2 示例标的定义（Demo 阶段）

| 项目 | 详情 |
|------|------|
| 标的全称 | 溜溜梅股份有限公司 |
| 上市市场 | 港交所主板 |
| 股票代码 | 06658.HK |
| 交易简称 | LLM |
| 业务属性 | 休闲食品研发、生产与销售，纯消费实体企业，与AI/大模型无业务关联 |
| 市场特性 | 因股票代码「LLM」与大语言模型缩写一致，引发散户非理性概念炒作，股价波动剧烈，具备典型情绪交易属性 |
| 选用价值 | 作为长尾非标资产示例，验证「任意有公开价格资产均可上链交易」的核心能力，同时降低普通用户认知门槛 |

### 1.3 核心特性

1. **去信任结算**：价格产生与结算完全基于 Monoracle 链上否决-套利机制（报价双边抵押 + 免许可仲裁），无链下数据源、无验证节点
2. **有限风险**：期权结构，无爆仓、无保证金追缴，用户最大亏损为投入本金（及手续费）
3. **灵活交易**：支持到期前反向平仓，随时锁定盈亏（✅ 对手方 = provider 抵押资金池，见 D-03）
4. **高性能底层**：基于 Monad 高性能 EVM 链，验证窗口仅 ~600ms（Monoracle 固定 2 slots）
5. **极简交互**：卡片式轻量化UI，核心操作一步直达，弱化区块链技术感

### 1.4 项目当前状态

- 脚手架搭建完成，目录结构对齐 Monoracle 项目；Monoracle 合约仅 **引用上游**（`github.com/dixia/monoracle`），本项目只保留 ABI（`abi/Monoracle.abi.json`）
- 核心产品规则与交互流程定稿（✅ 关键决策已确认，见 §八）
- Demo 版本进入开发准备阶段

## 二、核心业务规则

### 2.1 产品基础属性

- **产品类型**：欧式期权（仅到期按结算价兑付，支持到期前提前平仓）——✅ 盈亏模型 = **线性差价 PNL**（见 §八 D-02），非"奇异/二元"
- **期权期限**：可选时间到期。**Demo 默认固定 3 分钟**（✅ D-01；origin 原文 2.1 处写"demo 固定 1 分钟"，与 3.1 及 UI 的"3 个月"冲突，已统一）。Monad 出块 ~300ms，链上到期用 block 表达（3min ≈ 600 blocks）
- **交易方向**：同一标的两个方向——**看涨 / 看跌**。
  - ⚠️ **修正**：用户选「看跌」**不是** Monoracle 的 veto flow。用户买卖期权仓位；改用："结算时，看涨期权在 `结算价 > 开仓参考价` 时盈利，看跌期权反之"（见 2.4）。
  - 〔v0.7 R7〕"看涨（做多）/ 看跌（做空）"是**线性差价合约**语义的简称，非标准期权术语；产品本质 = 以 Monoracle 报价为标的的线性 PNL 合约。
- **结算资产**：链上统一使用测试币 `HKD` 作为计价/结算资产。⚠️ Monad 测试网无官方 HKD，需用可铸造 ERC20（`MockERC20`）发行 `LLM`（标的）与 `HKD`（计价）测试币；Monoracle 报价对 = `(base=LLM, quote=HKD)`，价格即 "HKD / LLM"
- **风险机制**：无爆仓、无保证金追缴、无强制平仓。用户最大亏损即开仓投入本金 + 手续费。⚠️ 期权本身无杠杆概念（最大亏损=本金），原文"大 leverage"已修正归入 PNL 模型（见 §八 D-02）
- **价格基准**：所有盈亏计算以 Monoracle canonical 价格为准（实时价 `getLatestPrice`；结算价同理）
- **开市权**：任何人可为任意标的创建市场（区别于 Polymarket 的平台审理制，Monoracle 支持任意资产对）——🔁 价格侧 Monoracle 已实现

### 2.2 做市商定价与手续费规则

> ⚠️ **区分两个价格**：Monoracle canonical 价 = 参考价（无升水、由否决仲裁约束真实）；IRMarket 的"成交价" = 参考价 ± 升水（IRMarket 自身的定价/手续费逻辑，Monoracle 不参与）。
>
> 🔁 做市商=Monoracle 的 provider：向 Monoracle 提交报价并双边质押（base+quote），获得否决风险收益（验证窗口内无人否决可原额取回，被否决则受损失）——**该机制 Monoracle 已实现，bot 直接驱动，无需 IRMarket 自研**。

1. **定价锚点**：做市商（provider）提交的报价严格锚定 溜溜梅（LLM）真实市场价（bot 抓取外部行情后调用 `submitQuote` 上链）
2. **报价升水机制（IRMarket 成交侧）**：前端展示给用户的期权交易价格，在参考价基础上上浮/下浮约 **1%**，以买卖价差形式隐性收取费用
   - 看涨开仓：成交参考价略高于市场参考价
   - 看跌开仓：成交参考价略低于市场参考价
   - ⚠️ 该"升水"是 IRMarket 定价层，**与 Monoracle 报价无关**；Monoracle 端报价就是真实市场价（否则会被否决套利惩罚）
3. **收益归属**：〔v0.7 R4〕⚠️ 原文同时使用两种**互斥**模型——"价差隐性收取"（升水嵌入成交参考价）与"直接划转至做市商账户"（显式扣费）。同一笔费不可能既是隐式又是显式，**待确认（§十 Q3）**：
   - **模型A（显式扣费）**：开仓按名义额扣 1% 划入做市商账户，PNL 用未调整参考价；
   - **模型B（价差嵌入）**：升水进开仓参考价（看涨 ×1.01 / 看跌 ×0.99），无单独划转，做市商收益体现在池残值与对赌结果中
4. **用户感知**：手续费不以单独字段展示，用户感知为交易滑点/买卖价差

### 2.3 交易与平仓规则

- **开仓**：用户选择方向、投入 QUOTE（HKD）数量，确认后链上锁定资金，生成持仓记录；持仓份数 = 投入 HKD ÷ 开仓参考价（✅ D-02）
- **反向平仓**：到期前可随时反向平仓锁定盈亏 ✅ **决策 D-03（Stage 1）**：对手方 = **IRMarket 自有资金池**（初始 QUOTE 流动性 + 市场内多空本金净额），按当前 Monoracle 参考价即时结算（用户卖回给池子）。〔v0.7 R3〕⚠️ 原文"用 provider 存入 Monoracle 的双边抵押资金承接"**技术上不可行**——该抵押品锁在 Monoracle 合约内，IRMarket 无法动用（见 §〇 R2）；资金池模型待 Q1/Q2 拍板。后续（Stage 2）升级为分级基金模式
- **平仓定价**：平仓价格同样遵循 1% 升水规则，以实时参考价为基准（✅ 参考价由持续报价 bot 维持新鲜，见 D-05）
- **结算时效**：平仓交易上链确认后，盈亏实时结算，剩余资金自动划转至用户钱包

### 2.4 结算规则

- **触发条件**：期权到期后自动结算（✅ **决策 D-04**）。看涨/看跌用户仓位的盈利**由系统自动结算**（bot 免许可触发，仿 Monoracle settle 机制），**UI 实时展示浮盈**，可一键领取到账；**结算价 = 到期时 bot 新报的一笔最终报价并结算**（✅ D-06，经合约源码验证可行：`submitQuote` → 2-slot 窗口后 `settleValidQuote` → `getLatestPrice` 即为该最新价）
- **价格依据**：⚠️ 修正——Monoracle **没有"到期日最终有效报价"这一概念**，每个报价只对应一个验证窗口。IRMarket 结算价 = **结算交易执行时** 调 `getLatestPrice(base=LLM, quote=HKD)` 读取的最新 canonical 有效价（由 Monoracle 否决仲裁保证其真实性，🔁 已实现）
- **盈亏判定**（✅ 决策 D-02：**线性差价 PNL**，以 Monoracle 参考价差计算；用户确认"核心是算 PNL"，模型形状不纠结）：
  - 看涨：`盈亏 = (结算价 − 开仓参考价) × 持仓份数`；结算价 > 开仓价 → 盈利，反之亏损
  - 看跌：`盈亏 = (开仓参考价 − 结算价) × 持仓份数`；结算价 < 开仓价 → 盈利，反之亏损
  - 持仓份数 = 投入 HKD ÷ 开仓参考价（名义单位），PNL 封顶于本金（无追缴）
  - ⚠️ 原文"按差价兑付收益；反之本金全部亏损"的**二元表述已弃用**，统一为线性差价 PNL（见 §八 D-02）
- **资金兑付**：结算完成后，盈利资金自动划转至用户钱包地址

## 三、完整业务全流程

### 3.1 前置流程：做市商建市（Demo 阶段）

> ⚠️ 修正：这不是"向 Monoracle 写入初始市场价"这么简单——provider 必须 **双边质押** base+quote 两种 ERC20 提交真实价报价。完整建市如下：
>
> 1. （脚本）铸造 `LLM` / `HKD` 测试币，并在 Monoracle 上以 (base=LLM, quote=HKD) 建立报价对
> 2. （脚本=provider）抓取 LLM 真实市场价 → 按价格比率双边质押调用 `submitQuote`，报价上链（🔁 Monoracle 已实现，验证窗口 2 slots）
> 3. （可选）等待 `settleValidQuote` 使首笔价格成为 canonical（🔁 任何人可结算；bot 可代结算）
> 4. 调用 IRMarket 合约创建期限 = 3min（demo）的期权市场，并向 **IRMarket 自有资金池**注入初始 QUOTE 流动性（〔v0.7 R6〕该池与 Monoracle 双边抵押品**完全分离**——Monoracle 抵押是报价的抵押，不是期权偿付池；偿付资金来源见 §十 Q1）
> 5. 市场生效，开放交易
>
> 后续加入分级基金机制（远期）。

> ❓→✅ **报价频率（决策 D-05）**：bot **持续报价**，频率以"**3 分钟 Demo 窗口内能完成一个完整流程周期**"为准（报价→窗口结算→用户开仓→平仓/到期→PNL 结算全链路走完 ≤ 3min）。每轮报价 2-slot 窗口（≈600ms）settle 后成为最新 canonical 价，供开仓/平仓/结算读取。

### 3.2 用户开仓流程（以看跌/做空为例）

1. 用户连接钱包，切换至 Monad 测试网（Chain ID 10143）
2. 在市场列表选择溜溜梅标的，进入详情页
3. 切换至「看跌」Tab，输入投入 QUOTE（HKD）数量
4. 系统实时计算持仓份数（= 投入 ÷ 开仓参考价）、预估盈亏、最大亏损（✅ D-02 线性差价模型）
5. 用户确认开仓，发起链上交易并签名
6. IRMarket 合约原子化执行：锁定用户资金 → 记录开仓参考价与持仓（参考价 = `getLatestPrice`）→ 计提升水
7. 交易上链确认，持仓生效

### 3.3 持仓与反向平仓流程

1. 用户在持仓页查看所有未平仓仓位与实时浮动盈亏（浮动盈亏 = f(当前 `getLatestPrice`，持仓参考价)，✅ D-02 线性模型）
2. 选择对应仓位，点击「反向平仓」（✅ D-03 provider 资金池接盘）
3. 弹出平仓确认卡片，展示平仓价格、预估盈亏
4. 用户确认后发起链上交易
5. IRMarket 合约按当前参考价计算平仓盈亏，扣除升水后划转资金
6. 对应持仓销毁，仓位关闭

### 3.4 到期结算流程

1. 期权到期后，持仓卡片「反向平仓」按钮替换为「结算」按钮（✅ D-04：到期由 bot 自动结算，UI 仅做展示/领取）
2. 系统展示最终结算价（= 结算 tx 时 `getLatestPrice` 的最新 Monoracle 报价，非"到期日历史报价"）与盈亏结果
3. bot 自动触发链上结算（任何人均可免许可触发）
4. IRMarket 合约读 `getLatestPrice`（🔁 Monoracle）计算最终盈亏
5. 兑付资金至用户钱包，仓位标记为已结算

### ✅ D-01 期权期限
- Demo 默认 **3 分钟**（≈600 blocks）；**UI 期限选择器需提供其它期限选项**（3min / 5min / 1h / 1d / 1month），默认选中 3min。合约支持多期限，Demo 主要走 3min 链路。

### ✅ D-02 盈亏模型（线性差价 PNL）
- 产品本质 = **基于 Monoracle 报价的期权**，核心是 **PNL 计算**，模型形状不纠结。
- 公式：`持仓份数 = 投入 HKD ÷ 开仓参考价`；看涨 `PNL = (结算价 − 开仓参考价) × 份数`，看跌反之；PNL 封顶本金（无追缴）。
- 结算价 / 平仓价 / 实时浮盈均读 `getLatestPrice`（Monoracle 最新有效报价）。
- 落地注意：结算价与开仓参考价的时间锚点（开仓时快照 vs 结算 tx 时最新报价）要在合约里显式记录，防止重入/抢跑。

### ✅ D-03 反向平仓对手方（Stage 1）〔v0.7 R3 改述，待 Q1/Q2 最终拍板〕
- 对手方 = **IRMarket 自有资金池**（初始 QUOTE 流动性 + 市场内多空本金净额）。⚠️ 原文"provider 存入 Monoracle 的抵押资金构成承接池"技术上不可行：该抵押品托管在 Monoracle 合约内，IRMarket 无法动用（见 §〇 R2）。
- 平仓按当前 Monoracle 参考价即时结算（用户卖回给池子）。
- 做市商风险敞口由 1% 升水收入（模型见 Q3）+ 池内残值覆盖。
- **Stage 2（远期）**：升级为 **分级基金（tranche fund）** 模式承接对手风险。
- 落地注意：pool 需在 IRMarket 内独立记账（用户资金 / 盈亏池 / 做市商收益三账户隔离）；池余额不足时的行为见 §十 Q2。

### ✅ D-04 到期结算触发
- **自动结算**：到期后由 bot（任何人均可免许可触发，仿 Monoracle settle）自动为看涨/看跌仓位结算盈利。
- **UI 只负责展示与领取**：展示最新 Monoracle 报价下的浮盈/最终盈亏，用户一键领取到账。
- **结算价（D-06，已确认可行）**：到期时 bot 用报价脚本 **再报一笔最终价** 并结算——`submitQuote`（双边质押）→ 2-slot 窗口（≈600ms，Monad 300ms 出块、2-slot finality）→ `settleValidQuote` 成为 canonical → IRMarket 结算 tx 里读 `getLatestPrice` 即得最终结算价。
- 落地注意：自动结算的 gas 承担与奖励（小额返还）需要在合约中定义，防止无人触发的资金僵死；`getLatestPrice` 只返回最新 settled 报价（无 quoteId 选择），demo 中 bot 为唯一 provider 故确定，多 provider 场景需另行冻结快照（远期）。

### ✅ D-05 报价频率
- bot **持续报价**，频率以"**3 分钟 Demo 窗口内可完成一个完整流程周期**"为准（建市报价→窗口结算→用户开仓→平仓/到期→PNL 结算，≤ 3min 全部走完）。
- 每轮报价经 2-slot 验证窗口（≈600ms）settle 后成为最新 canonical 价；连续报价维持参考价新鲜，平仓/结算可信。
- 落地注意：报价 interval 为**可配参数**（`bot/.env`：`QUOTE_INTERVAL_SECONDS` / `QUOTE_INTERVAL_BLOCKS`），兼顾 gas（Monad 按 gas_limit 计费）与 3min 窗口。

### Q1（对应卡点 B1，高）期权盈亏的对手方与资金池模型？
- **A（推荐）**：IRMarket 自有资金池 = 做市商初始注入 QUOTE + 多空双方本金净额抵消 + 做市商承担残值风险；Monoracle 只负责出价，两层资金完全分离。
